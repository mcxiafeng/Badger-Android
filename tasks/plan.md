# Android + Go 当前闭环验证计划

日期：2026-11-22。依据：用户要求“先把完整闭环跑起来”。范围为当前 Android :app 与 Go 私有资料服务；JS provider 为后续独立功能。本轮不自动提交或部署。

## 验收与依赖

1. 当前源码构建及账号/认证/同步/导入/冲突聚焦回归：生成本轮 APK、后端二进制与真实测试报告。历史结果仅作背景。已知本地 C2 编译器崩溃按既有临时 C1 测试配置处理，保留断言。
2. 独立合成服务与只读模拟器：通过真实登录表单，核对双向编辑、私有图片、进程重启后恢复与退出远端撤销。依赖本轮构建。
3. 扩展完整链路：本地资料先保留，登录不自动上传，确认导入后同步；另一账号不可见该资料，重新登录原账号可继续。补充离线修改/恢复与冲突处理的实际可执行检查。依赖步骤 2。
4. 对实际失败定位并做最小修复，重跑原失败与受影响检查；本轮若没有源码缺陷，不扩大重构。
5. 保存脱敏验证记录，清理本轮自建进程、测试会话与临时凭据。只处理归属明确的测试资源，保留旧结果及用户已有设备/资料。

## 边界

- 不截图，使用无障碍树、日志、HTTP/数据库与图片摘要。
- 不操作真实 Data、生产账号、旧 Java 数据库或他人模拟器。
- 真机、NFC、生产部署、全历史数据迁移不以本轮结果冒称已验证。
- 测试脚本与日志放本轮唯一 build 子目录，不复用旧的 android-e2e-current 状态。
