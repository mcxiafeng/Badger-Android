# 本地资料与远端图片的有界加载

日期：2026-11-22。适用当前 Android `:app` 与 `F:\GolandProjects\BadgerServer`。本轮沿用本地可独立使用、登录后按账号同步的方式。

## 资产状态

文字资料和资产描述继续存入账号数据库。同步完整快照不再要求把全部资产下载到手机，`assetId / canonicalSha256 / canonicalSize / canonicalMime` 与“图片当前在本机可用”分别成立。

新接收的资产保存小型 `.asset.json` 引用。不同业务图片拥有独立引用文件，删除一个头像不会删除另一个背景引用。引用文件不属于缓存；缓存淘汰不会将图片字段置空，也不会产生一条清除远端头像的同步修改。

| 文件类型 | 本轮保留语义 |
| --- | --- |
| 本地业务原件、尚未上传的固定副本 | 不参与普通缓存淘汰 |
| 现有版本下载的 PNG 及业务副本 | 保留，不在本轮自动迁移或删除 |
| 新远端资产引用 | 持久保存描述，不复制整张图片 |
| 可重新下载的图片字节 | 进入 Coil 的单一磁盘 LRU，候选预算固定 100 MiB |
| Coil 解码图片缓存 | 固定 32 MiB；页面正在持有的显示位图、解码及网络临时缓冲另计 |

上传回执在数据库中持久化后，仅删除本次生成的 `.source` / `.upload.png` 暂存副本。回执丢失或尚未确认时保留这些副本并复用原 mutationId；业务原件、local 空间的导入来源和旧版本文件不受这项清理影响。

100 MiB 不是整个 App 或用户资料的空间上限。数据库、持久引用、用户原件、待上传副本、旧版本业务文件和缓存索引均需分别核算。Coil LRU 清理异步执行，临时写入和仍打开的条目也不能被描述为严格瞬时上限。

## 显示与兼容

屏幕要求的宽高都不超过 256 px 时取缩略图；详情及原图用途取规范原图。原图逐项校验长度与快照摘要，错误响应不进入可复用缓存。缩略图需要独立表示标识、源 canonical 摘要与自身摘要，编码不超过 512 KiB、长边不超过 256 px。

缩略图使用 `GET /api/v1/assets/{id}?variant=thumbnail`。新服务端返回：

- `X-Badger-Asset-Variant: thumbnail`
- `X-Badger-Asset-Sha256: <缩略图实际摘要>`
- `X-Badger-Asset-Canonical-Sha256: <原图 canonicalSha256>`

旧服务端会忽略 query 并返回原图。客户端在读取正文前发现缺少变体标识，关闭响应，再按原图端点和 16 MiB 上限下载并校验；不会将未经确认的响应直接认作小图。此回退仍会消耗原图带宽。429、鉴权失败和错误摘要不会通过原图重试掩盖。

图片缓存键包含固定账号空间（实例、用户、世代）、资产 ID、原图摘要、表示与规则版本。请求捕获固定会话，拒绝重定向和 Cookie；会话或当前账号变化时丢弃迟到响应。命中本地缓存仍检查当前账号，已缓存内容可离线显示；未缓存图片离线时保留文字与引用。

从文件读取、下载、排队到解码 Source 关闭，最多同时持有两路许可；缩略图网络请求单路执行，与服务端冷缓存时的单路生成能力配合，避免同一手机的并发冷请求互相触发 429。原图和缩略图都返回文件支撑的 Source，缓存快照保持到解码结束。完整原图不会作为 Buffer 无界排队，缓存摘要改为流式校验。固定数量互斥锁合并同一缓存键的竞争，不为每张历史图片保留一个无限增长锁表。原图单份响应上限仍为 16 MiB，下载校验可能短暂持有额外数组副本；这些缓冲及页面显示位图不计入 32 MiB 解码缓存预算。

Application 在启动时显式注册 Hilt 图片加载器的惰性工厂，并始终从真实 Application 解析依赖；请求仍携带固定 AccountContext，避免包装 Context 使首次请求落到默认 Coil 加载器。AccountContext 同时把系统组件回调注册和注销委托到底层 Context，避免自身作为 applicationContext 时发生回调递归；文件目录和业务偏好的固定账号隔离不变。

同步仍读取完整文字快照。事务内增加标识反向索引与 ID 分配高水位缓存，减少恢复大量记录时重复遍历整个映射表；索引不跨事务复用，不改变持久化 `id/` 键、保留 ID、kind / custom / system 命名空间或冲突裁决规则。

## 关键状态与失败恢复

| 初始条件与事件 | 原行为 | 本轮行为与不变量 |
| --- | --- | --- |
| 远端新增大量有图联系人，网络中断 | 同步先遍历资产下载，文字应用受图片可用性影响，另复制业务图片 | 完整快照核对后持久化描述与引用；图片只在显示时读取，缺图不等于清空字段 |
| 已缓存图片被 LRU 淘汰，设备离线 | 旧业务文件不受 Coil 预算约束 | 保留持久引用，显示暂不可用；文字可搜索，联网后按摘要重取，不产生头像删除命令 |
| 图片上传服务端提交后回执丢失 | 保留固定上传副本与原 mutationId | 继续保留副本直到回执持久化；重放确认后只清理生成的上传暂存，不删除业务原件 |
| 请求发出后切账号 | 依赖固定会话检查保护同步 | 图片在缓存查询前及结果返回后检查账号；迟到请求不能填充另一用户的缓存，账号空间含世代 |
| 修改名片夹背景后取消 | 原路径被立即删除，数据库仍引用旧文件 | 已保存原背景不在草稿阶段删除；取消只清理本轮新草稿，提交失败时原背景仍可读 |

状态表是设计与代码路径对比；具体通过范围以本轮测试报告为准。

## 列表与搜索

联系人分页、搜索分组、标签窗口和稳定滚动锚点由本轮联系人纵切实现。文字保持完整本地保存；Room 主数据库版本保持 v6。额外搜索索引只保存可重建的本地派生数据，不进入同步协议。

## 验证边界

具体测试、容量数据、APK 测量和设备限制见 [本轮验证记录](bounded-loading-verification.md)。旧闭环记录仅作背景，不作为本次通过证据。容量验证使用合成资料与独立测试环境，禁止设备截图，不读取或修改用户已有设备资料。

公开名片、JS provider、OCR 模型可选下载及大图片完整离线备份仍需各自的协议与交付验证，本轮存储优化不代表这些能力已经交付。
