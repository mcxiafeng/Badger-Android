# 添加平台页面

添加平台使用独立的 `Route.AddPlatform(contactId)`，联系人详情、我的名片和首次引导共用该页面。已有平台的编辑继续使用原编辑入口。

## 自动获取

首屏为图标和多行输入框。每行一个平台账号或链接，输入后在本机识别并显示结果，确认保存后才写入。

```text
微信：wxid_example
QQ: 123456
GitHub: octocat
https://space.bilibili.com/42
https://xhslink.com/example
```

- 平台名称、注册别名和已知域名用于识别；域名按边界匹配，优先匹配更具体的域名。
- 仅有数字或无平台标记的账号不会被猜成 QQ、B 站等平台。
- 分享文字中可以包含一个链接；一行多个链接需要拆行。
- 短链接保留原链接，新页面的识别过程不访问输入中的网址。昵称、头像等联网补全仍可从已有平台同步入口执行。
- 自动输入最多 100 行、20,000 个字符。超限保留输入并提示分批处理，不截断后保存。

## 手动添加

“手动添加”打开页内的平台列表，提供圆形平台图标、名称、拼音首字母分组、字母定位和搜索。搜索覆盖名称、注册别名、字段 key 和首字母；已有平台与待添加平台有文字标记。

选择平台后填写账号或链接，可以填写昵称。抖音、小红书等保留只存账号的能力；网站需要完整的 HTTP/HTTPS 链接。自定义平台从列表上方进入。“添加到列表”把手动条目放入待添加列表，与自动识别条目统一保存。

## 动画与排版

- 三个页内步骤统一使用“添加平台”顶栏，通过 150ms 的淡入淡出和小幅纵向位移表达前进、返回。转场按步骤标识触发，输入文字时不重播整页动画；退出内容读取原状态快照。
- 各步骤使用独立的 SaveableStateProvider 保留滚动位置；从表单返回手动列表时恢复原位置与选中字母。
- 结果新增、移除和搜索过滤使用短时列表动画，不使用回弹或循环装饰。步骤切换时清除旧输入焦点并收起键盘。
- 输入、表单和底部操作对齐，宽屏内容区最大 720dp；顶部留白、分组间距、头像和行高使用现有设计 token。
- 联系人和平台列表共用 `AlphabetIndexBar`：可见栏宽独立设为 28dp，常规字距约 14dp，并先按整数像素分配行高，再计算拖动命中，避免密集字母末尾被逐项取整挤压。触控容错使用 Compose 的扩展命中，避免把触控宽度当作视觉占位。联系人侧边预留相同的 28dp，缩窄后也验证相邻列表点击不会被索引抢走。搜索框支持清除查询。
- 点击字母平滑定位；连续纵向拖动立即定位，只在目标字母改变时分发，不争抢主 Tab 的横向手势。当前字母高亮，临时大字预览在操作结束后短暂保留；取消手势立即清除预览，重复点击会更新预览截止时间。
- 索引是一个可调节的读屏复合控件，提供逐字母调整和可用字母操作菜单。普通字母沿用主题小字号，只在高度不足时适配；星标改为定尺寸矢量图，不参与整栏文字的字体回退测量。
- 预览主框在正常字号下为 64dp 方形，文字采用主题 title2；随系统字号等比例放大。无条目的说明放在主框外，避免将预览框撑宽或拉长。
- 联系人保留“我的名片”和完整 A–Z，并补上 `#`；无数据的字母弱化且不触发定位。目标位置依据实际展示的联系人列表建立，包含搜索栏、提示和名片的固定项偏移。联系人内容与底部悬浮动作避让索引热区。
- 识别失败行使用错误图标与错误色，保留具体行号和原因。待添加条目的移除按钮读屏描述包含平台名称。

## 状态与数据边界

- 当前存储结构每个联系人每种平台只保留一条。已有平台和重复输入明确提示，不覆盖原资料；有未处理的识别错误时不提交。
- `AddPlatformViewModel` 管理输入、搜索、表单、待添加条目和提交状态。`SavedStateHandle` 使用显式 Bundle 字段恢复输入，避免依赖 Gson 对页面私有类型的反射。
- 保存期间拦截重复提交和返回；失败保留输入，可以重试。离开未保存的任务需要确认放弃。
- Repository 在现有 `contactMutex` 中重读并查重，批量 Room `@Insert` 在事务内写入。并发重复或联系人不存在时不报告成功。
- 普通联系人写入其 `contactId`，我的名片和首次引导写入 `MY_CONTACT_ID`。未改变 Room schema、平台字段结构或依赖版本。
- 联系人详情在恢复显示时重读资料；首次引导通过 ViewModel 的资料 Flow 更新列表。
- 新日志只记录操作、数量和状态，不打印输入原文、分享参数或账号。
