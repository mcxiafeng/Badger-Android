# 本地用户、账号隔离与完整同步

本功能覆盖 Android `:app` 和服务端私有同步 schema 2。它不改变公开名片、二维码或 NFC 的分享白名单。

## 用户空间

- 首次使用及旧版本资料属于一个持久的“本地用户”。旧 `badger_database` 原地保留，不根据历史登录会话猜测资料归属。
- 云端空间按服务器实例 ID、用户 ID、数据世代隔离数据库、图片文件、业务配置和同步状态。用户名、连接 URL、token 都不是资料主键。
- 退出返回本地用户，保留云端空间及未同步资料；重新认证同一账号可继续使用。远端撤销在限时清理区间内继续执行，不随旧 ViewModel 销毁而取消；旧空间的退出请求不能清理新会话。服务器恢复造成世代变化时保留旧空间，不把旧待写重放到新世代。
- 切换空间会清理旧 ViewModelStore 并重建 Activity/导航。旧任务固定持有原空间的 DAO、文件 Context 和会话，不能在回包时改用新账号。
- AI 配置、短链配置及其凭据按用户空间隔离；主题、导航外观和系统权限属于设备。第三方 API 密钥不会随名片资料上传。

## 同步范围

联系人与我的名片的姓名、备注、简介、平台完整条目、系统/自定义联系方式、字段定义及设置、头像、名片背景；名片夹说明、背景、颜色、成员及重复扫描来源记录；标签颜色、显示方式及关联来源/置信度/时间，均属于私有业务同步。

FTS、拼音、图片缓存等派生内容在本机重建。文件路径和本地自增 ID 不进入协议，记录、子项及资产使用持久 UUID。nullable 平台值、自定义跳转 scheme、我的名片标签/夹关联保存在完整私有扩展中，不伪造旧协议要求的账号值。

## 登录导入

登录不会自动上传本地用户的资料。有可导入内容时先询问；拒绝不改变任一侧的业务资料，可以从“用户与同步 → 本地资料导入”再次进入。

预览按稳定记录 ID 保存选择。联系人同名、同平台值仅提供重复候选，不自动认定是同一个人。可跳过、新建副本或明确选择合并目标；同名标签新建副本时重命名。图片复制到目标用户自己的文件空间，原件保持不变。新设备未修改的内置字段默认值会采用云端已有配置，不作为一次用户编辑覆盖云端。

导入合并没有共同祖先：空字段允许补充，已有不同内容进入持久冲突，未经裁决不会被下一轮快照自动上传覆盖。同一批次不允许多条联系人等资料同时写入同一合并目标；过期预览可明确重建并重新确认选择。导入提交在目标 Room 事务中保存资料及回执；云端命令逐条确认，返回页面或网络取消不代表撤销服务端已接受的写入。

## 同步与冲突恢复

- 每个用户库持久保存 UUID 映射、远端 Shadow、不可变待确认请求、完整快照水位、冲突与导入回执。
- 完整快照校验服务器/用户/世代、schema、分页数量、原始 rows 字节摘要及 manifest 摘要后才事务应用。不完整、损坏或回退的快照不清空本机数据。
- 超时后先以同一 mutationId 和准确原正文核对回执。确认某次编辑成功不能清掉发送后产生的新编辑。上传确认水位与快照水位分别保存。
- 同一资料使用 base/local/remote 三方比较，以已保存业务记录为准，尚未提交的输入不进入同步。不同字段的修改可合并；相同字段分歧、删除与编辑冲突等待用户选择。普通联系人还可保留两份。
- 标签遵循名称唯一键：尚未上传的新标签可对应到云端同名标签；已有不同远端身份的标签不会自动合并，重命名冲突会给出“调整标签名称”入口。
- 删除联系人有未确认编辑/关联变化时先保留联系人及关系。字段删除若遇到云端新引用，会保留本机意图并暂停关联应用；用户先采用云端定义、核对引用后再删除，避免隐式批量擦除其他联系人字段。
- 图片资产缓存与各业务引用使用不同文件。替换一个头像不能删除其他联系人或背景仍在使用的图片；“保留两份”会分离文件，并携带本机模型没有独立列的核心资料。
- 同一联系人依赖多个待恢复字段时，可逐个恢复定义，全部依赖实际可用后才应用挂起联系人，不因另一字段尚未恢复而回滚已确认的选择。

## 状态变化与兼容

| 场景 | 原行为 | 新行为 |
| --- | --- | --- |
| 本地、A、B 切换 | 替换会话，仍读取同一业务库 | 固定数据库、文件、配置和页面生命周期，退出回本地 |
| 登录时已有本地资料 | 没有归属或复制流程 | 先预览并确认，保留源，稳定 ID 与回执避免重复 |
| 两端修改或删除/编辑相遇 | 没有业务同步冲突基线 | 保留本机意图与远端版本，裁决后以新命令条件写 |
| 写入后响应丢失 | 没有业务待确认请求 | 原命令重放核对，发送后的新编辑保留 |

本机增加同步元数据表，采用非破坏性 Room v5→v6 迁移。不能以降 schema、清库或重新安装旧包作为代码回退方式；旧版构建不具备读取新本机库的兼容承诺。

## 服务端兼容与边界

继续使用 `/api/v1/sync/mutations`、`/snapshots` 及私有资产 API。全部同步请求（含分页）发送 `X-Badger-Sync-Schema: 2`，通过 `/api/v1/sync/capabilities` 协商支持范围。

服务端在同一事务中维护扩展资料、owner 引用、根版本、revision 及幂等回执。启用 schema 2 的账号拒绝不兼容旧端读写，避免旧 replace 擦除新字段；原 schema 1 向量及尚未升级的账号保持兼容。启用完整同步后，旧客户端需要升级才能继续同步该账号。

沿用现有有界协议：单条业务值 128 KiB、mutation 256 KiB；字段/平台、成员及文本各有数量/长度限制。超限会保留本机原文并报告待处理，不截断后伪报成功。连接地址变更不会把旧凭据直接发给新地址，需重新认证切换到已验证入口。

回退应暂停同步/导入并保留各空间和待写，不降 schema、不清库。本次实现不涉及自动部署或生产数据迁移操作。
